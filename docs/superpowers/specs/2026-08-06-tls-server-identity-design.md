# TLS Server Identity Design

**Status:** Approved by issue #6 and the autonomous Phase 1 product loop  
**Date:** 2026-08-06  
**Scope:** Authenticate one canonical HTTPS origin over an already verified direct TCP connection

## Problem

`originweave-network` proves that one policy-approved canonical socket became the exact operating-system TCP peer. TCP peer equality does not prove that the peer is authorized to represent the requested web identity. An approved address can present an untrusted, expired, not-yet-valid, wrong-name, malformed, or otherwise invalid certificate. A TLS adapter can also negotiate an unexpected application protocol, leak traffic secrets, resume a session under different authority, or silently disable authentication.

OriginWeave therefore requires a separate TLS identity boundary before it can claim authenticated HTTPS transport.

## Goals

1. Add an independently reusable `originweave-tls` crate.
2. Consume an existing `DirectTcpConnection`; never open, reconnect, resolve, or proxy a socket.
3. Accept only canonical HTTPS `Origin` values.
4. Derive a DNS or literal-IP reference identity from the canonical origin.
5. Use rustls 0.23.42 with the `ring`, `std`, and `tls12` features, TLS 1.2 and TLS 1.3 only, a fixed explicit time provider, a caller-supplied trust-root bundle, default WebPKI verification, no client authentication, no session resumption, no early data, no secret extraction, and `NoKeyLog`.
6. Send SNI only for DNS reference identities; rustls `ServerName::IpAddress` sends no SNI.
7. Offer only an explicit bounded ALPN allow-list and reject absence when the policy requires negotiation.
8. Enforce a monotonic total handshake deadline by setting each blocking socket read or write timeout to the remaining deadline before the I/O call.
9. Verify the inherited TCP peer before and after the TLS handshake.
10. Bound trust roots, server-presented certificate count and bytes, ALPN values, and handshake duration before exposing an authenticated stream.
11. Emit credential-free evidence for the verified identity, transport, protocol, certificates, trust bundle, trusted time, revocation configuration, and timing.
12. Preserve underlying destination, I/O, rustls, trust-store, and X.509 parsing errors through standard error chains where safe.

## Non-goals

- DNS lookup or refresh
- TCP connection creation or pooling
- proxy or PAC routing
- HTTP request or response semantics
- QUIC or HTTP/3
- system trust-store discovery or automatic root updates
- OCSP or CRL network fetching
- client certificates
- Encrypted ClientHello
- delegated credentials
- Chromium Network Service integration
- download or MIME policy

These remain separately reviewable adapters.

## Dependencies

Production dependencies are pinned through `Cargo.lock`:

- `rustls = 0.23.42`, default features disabled, features `ring`, `std`, and `tls12`;
- `sha2 = 0.10.9` for SHA-256 evidence identifiers;
- `x509-parser = 0.18.1`, default features disabled, for bounded leaf-certificate validity and SPKI extraction;
- `originweave-core` and `originweave-network` path dependencies.

Test-only dependencies use `rcgen = 0.14.8` and the same rustls crate to create deterministic local certificate hierarchies and TLS servers. Exact dependency versions are regenerated by Cargo and reviewed in `Cargo.lock` rather than edited approximately.

## Crate boundary

```text
originweave-tls
├── src/lib.rs            public API and crate-level safety contract
├── src/identity.rs       canonical HTTPS origin to reference identity
├── src/trust.rs          bounded immutable trust-root bundle
├── src/policy.rs         ALPN, timeout, certificate, and revocation policy
├── src/handshake.rs      fixed-time rustls client and deadline-bound I/O
├── src/evidence.rs       certificate and protocol evidence
└── src/error.rs          deterministic standard errors
```

The crate performs no DNS, TCP connect, proxy, HTTP, Chromium, or model I/O. It consumes one verified TCP stream and returns one authenticated TLS stream only after every policy and evidence check succeeds.

## Public API

### Trust roots

```rust
pub struct TrustRootBundle { /* private */ }

impl TrustRootBundle {
    pub fn new(
        bundle_identifier: TrustBundleIdentifier,
        certificate_der: impl IntoIterator<Item = Vec<u8>>,
    ) -> Result<Self, TlsError>;
}
```

The constructor:

- accepts `1..=256` root certificates;
- accepts at most 2 MiB total encoded bytes;
- rejects an empty certificate;
- sorts and deduplicates DER bytes for a stable semantic bundle;
- adds every certificate to a new `rustls::RootCertStore` and fails if any root is invalid;
- computes `sha256:` over a domain-separated, count- and length-prefixed canonical sequence;
- stores only immutable DER values, the built root store, identifier, count, byte count, and hash.

The identifier is a bounded ASCII policy label, not a credential. It must contain 1–128 bytes from `[A-Za-z0-9._:-]`.

### Policy

```rust
pub struct TlsClientPolicy { /* private */ }

impl TlsClientPolicy {
    pub fn new(
        trusted_time: UnixTime,
        handshake_timeout: Duration,
        alpn_protocols: impl IntoIterator<Item = Vec<u8>>,
        alpn_requirement: AlpnRequirement,
    ) -> Result<Self, TlsError>;
}
```

Bounds:

```rust
pub const MAX_TLS_HANDSHAKE_TIMEOUT: Duration = Duration::from_secs(30);
pub const MAX_ALPN_PROTOCOL_COUNT: usize = 8;
pub const MAX_ALPN_PROTOCOL_LENGTH: usize = 255;
pub const MAX_ALPN_TOTAL_BYTES: usize = 1_024;
pub const MAX_SERVER_CERTIFICATE_COUNT: usize = 16;
pub const MAX_SERVER_CERTIFICATE_BYTES: usize = 1_048_576;
```

ALPN identifiers must be non-empty, unique, and within the per-value and total bounds. `AlpnRequirement::Optional` records explicit absence; `Required` rejects absence after the handshake. Rustls also checks that any selected ALPN value was offered.

The first slice has one explicit revocation configuration:

```rust
pub enum RevocationStatus {
    NotConfigured,
}
```

It never claims OCSP or CRL verification when no revocation input was configured.

### Handshake plan

```rust
pub struct TlsHandshakePlan { /* private */ }

impl TlsHandshakePlan {
    pub fn new(
        origin: Origin,
        connection: DirectTcpConnection,
        trust_roots: TrustRootBundle,
        policy: TlsClientPolicy,
    ) -> Result<Self, TlsError>;

    pub fn authenticate(self) -> Result<AuthenticatedTlsConnection, TlsError>;
}
```

The plan is not cloneable and consumes the direct TCP connection. Validation before TLS I/O:

1. origin scheme is exactly HTTPS;
2. origin contains a canonical DNS, IPv4, or IPv6 host;
3. origin host produces a valid rustls `ServerName`;
4. direct connection evidence requested peer equals observed peer;
5. direct stream `peer_addr` still equals the inherited observed peer;
6. trust root and policy bounds are already valid.

### Authenticated connection

```rust
pub struct AuthenticatedTlsConnection { /* private */ }

impl AuthenticatedTlsConnection {
    pub fn stream(&self) -> &rustls::StreamOwned<ClientConnection, TcpStream>;
    pub fn stream_mut(&mut self) -> &mut rustls::StreamOwned<ClientConnection, TcpStream>;
    pub fn evidence(&self) -> &TlsConnectionEvidence;
    pub fn into_parts(self) -> (
        rustls::StreamOwned<ClientConnection, TcpStream>,
        TlsConnectionEvidence,
    );
}
```

The stream becomes observable only after certificate validation, reference-identity validation, protocol checks, ALPN policy, peer revalidation, certificate bounds, evidence extraction, and timeout restoration succeed.

## Reference identity

```rust
pub enum TlsReferenceIdentity {
    Dns(String),
    Ip(IpAddr),
}
```

The parser consumes only the canonical `Origin` string:

- `https://example.com` and `https://localhost` produce DNS identities and SNI;
- `https://192.0.2.1` produces an IPv4 identity and no SNI;
- `https://[2001:db8::1]` produces an IPv6 identity and no SNI;
- explicit ports do not change the identity;
- HTTP and malformed authority fail before handshake I/O.

Rustls WebPKI validation follows SAN-based DNS and IP matching. Common Name fallback is not implemented by OriginWeave. RFC 9525 is the normative service-identity reference and supersedes RFC 6125.

## Trust and time configuration

A private `FixedTimeProvider` implements rustls `TimeProvider` and returns the policy `UnixTime`. Configuration uses:

```rust
ClientConfig::builder_with_details(
    Arc::new(rustls::crypto::ring::default_provider()),
    Arc::new(FixedTimeProvider::new(trusted_time)),
)
.with_protocol_versions(&[&rustls::version::TLS13, &rustls::version::TLS12])?
.with_root_certificates(root_store)
.with_no_client_auth()
```

Then the crate explicitly sets:

```text
resumption = disabled
enable_early_data = false
enable_secret_extraction = false
key_log = NoKeyLog
send_ticket_request = None
cert_compressors = []
cert_decompressors = []
check_selected_alpn = true
ALPN = validated caller allow-list
SNI = true for DNS identity; false for IP identity
```

No production path calls `ClientConfig::dangerous` or installs a custom certificate verifier.

## Deadline-bound handshake

`TcpStream::set_read_timeout` and `set_write_timeout` receive the remaining monotonic deadline before every blocking I/O. The loop performs only the I/O rustls currently requests:

```text
while client.is_handshaking():
    verify peer is unchanged
    if wants_write: set remaining write timeout; write_tls
    if wants_read:  set remaining read timeout;  read_tls; process_new_packets
    reject zero progress or elapsed deadline
```

Timeout-like I/O errors and elapsed deadlines become `HandshakeTimedOut`. Other I/O errors remain `HandshakeIoFailed`. Rustls protocol and certificate errors are classified separately. After success, socket timeouts are cleared; failure never exposes the stream.

This is a handshake deadline, not a post-handshake HTTP deadline. The later HTTP adapter owns request and response elapsed-time budgets.

## Certificate and protocol evidence

After a successful handshake, the crate requires:

- protocol version is TLS 1.2 or TLS 1.3;
- a negotiated cipher suite exists;
- ALPN satisfies the explicit policy;
- `peer_certificates()` is present and contains `1..=16` certificates;
- total presented DER bytes are at most 1 MiB;
- the leaf parses as one complete X.509 DER object;
- the stream peer remains unchanged.

Evidence contains:

```text
canonical origin
requested and observed TCP peer
DNS or IP reference identity
TLS 1.2 or TLS 1.3
cipher-suite identifier and stable rustls debug label
negotiated ALPN or explicit absence
leaf certificate SHA-256
leaf SubjectPublicKeyInfo SHA-256
ordered server-presented certificate SHA-256 list
server-presented certificate count and total bytes
leaf notBefore and notAfter Unix timestamps
trust-bundle identifier, SHA-256, root count, and encoded bytes
trusted verification time
revocation status = not_configured
handshake duration and configured deadline
```

Rustls exposes the server-presented certificate chain accepted during the verified handshake, not the exact internally constructed PKIX path or selected trust anchor. OriginWeave therefore labels these values `presented_certificate_hashes` and does not falsely claim exact path-construction evidence.

Hashes use lowercase `sha256:` identifiers. Certificate bytes, subject names, serial numbers, URLs, session tickets, key material, and plaintext are not retained in evidence.

## Error model

`TlsError` distinguishes:

- invalid or non-HTTPS origin;
- invalid trust-bundle identifier;
- empty, excessive, duplicate-only, or malformed trust roots;
- invalid timeout or ALPN policy;
- inherited TCP peer inconsistency;
- rustls configuration failure;
- handshake timeout;
- handshake I/O failure;
- unknown issuer;
- expired certificate;
- not-yet-valid certificate;
- service-identity mismatch;
- revoked or unknown revocation status when future revocation policy requires it;
- invalid certificate or chain;
- unsupported protocol version;
- absent or unexpected ALPN;
- missing, excessive, or malformed peer certificates;
- post-handshake peer mutation;
- timeout restoration failure.

Public messages are deterministic and credential-free. Underlying `io::Error`, `rustls::Error`, root-store, and X.509 parse errors are retained only as standard sources or bounded debug categories, never as certificate dumps.

## Testing

### Real local integration

A test CA issues local server certificates and starts a rustls `ServerConnection` over an ephemeral loopback `TcpListener`. The client first obtains a real managed-loopback `DirectTcpConnection`, then authenticates it.

Cases:

- DNS SAN `localhost` succeeds;
- wrong DNS SAN fails without Common Name fallback;
- untrusted CA fails;
- fixed trusted time rejects expired and not-yet-valid certificates;
- IPv4 SAN succeeds for `https://127.0.0.1`;
- IPv6 SAN succeeds where the host supports loopback IPv6;
- DNS certificate does not authenticate an IP origin;
- required ALPN succeeds and absence fails;
- optional ALPN records explicit absence;
- negotiated ALPN is one of the offered values;
- TCP requested and observed peers remain unchanged.

### Deterministic policy and error tests

- HTTP origin fails before TLS bytes are exchanged;
- invalid root identifiers and malformed roots fail;
- zero and excessive timeout fail;
- empty, duplicate, excessive-count, excessive-length, and excessive-total ALPN inputs fail;
- missing, excessive-count, excessive-byte, and malformed certificate inputs fail before stream exposure;
- rustls certificate errors map to typed product errors;
- read, write, peer, and timeout restoration I/O errors retain their sources;
- one-shot plan cannot be replayed.

A private handshake-I/O abstraction may simulate rare timeout and peer-mutation outcomes. It may not replace rustls certificate verification or the public real-socket integration path.

### Static governance

Python contracts require:

- `originweave-tls` workspace membership;
- exact rustls feature and version policy;
- no `dangerous()` or custom verifier in production;
- no `TcpStream::connect`, `ToSocketAddrs`, DNS, proxy environment, key-log file, early data, session resumption, or client certificate production path;
- explicit fixed time provider, root store, protocol versions, peer checks, certificate bounds, and ALPN policy;
- documents distinguish TCP peer, TLS identity, HTTP, proxy, and Chromium authority.

## Standards basis

- RFC 5280 defines PKIX certificate and CRL validation.
- RFC 8446 defines TLS 1.3; rustls also supports TLS 1.2 under its safe configured suites.
- RFC 9525 defines current TLS service-identity verification, requires SAN-based DNS/IP identities, and supersedes RFC 6125.
- rustls 0.23.42 provides explicit roots, fixed time provider injection, TLS version selection, WebPKI verification, ALPN, peer certificates, negotiated protocol and suite evidence, disabled resumption, disabled early data, and no key logging by default.
